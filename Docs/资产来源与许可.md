# Online Action RPG Tech Demo 美术素材方案与许可记录

> 文档版本：v0.1 规划版  
> 创建日期：2026-08-13  
> 适用阶段：项目规划期、MVP 开发期、作品集展示期  
> 核心原则：只使用来源清晰、授权明确、可在作品集 Demo 中解释的素材

---

## 1. 方案目标

本项目的美术素材方案服务于三个目标：

1. **降低早期开发阻力**：先用白模、免费动作和低成本合法素材跑通动作战斗、网络同步、资源加载和演示链路。
2. **保持作品集干净**：不使用从商业游戏客户端中提取的模型、贴图、动作、特效或角色 IP。
3. **形成求职证据**：把素材来源、License、导入方式和替换策略记录下来，体现工程交付意识。

本项目不是美术展示项目，第一优先级是证明客户端工程能力：

```text
动作状态机
  -> 技能帧事件
  -> HitBox / HurtBox
  -> 网络同步
  -> Addressables 异步加载
  -> Debug 面板
  -> 性能记录
```

---

## 2. 禁用素材范围

以下素材不得用于公开作品集、GitHub 仓库、演示视频或简历项目包：

- 从《原神》《崩坏：星穹铁道》《绝区零》《鸣潮》等商业游戏客户端中提取的模型、贴图、动作、特效、音频或 UI。
- 未明确允许游戏使用的 MMD 模型、二创模型、粉丝角色模型。
- 带有明确商业 IP、Logo、角色名、品牌标识的模型或贴图。
- License 标注为 `Non-Commercial`、`Editorial`、`No Derivatives` 且项目用途不满足限制的素材。
- 只允许在特定引擎中使用的素材，例如只允许 Unreal Engine 使用的 Epic 官方内容。

面试表达中可以说明：本项目参考动作 RPG 的技术问题和表现结构，但不复用未授权商业游戏资产。

## 3. 阶段化素材策略

### 3.1 阶段一：白模技术验证

目标：尽快跑通第三人称动作、技能、受击、血量和网络同步。

推荐素材：

| 类型 | 推荐来源 | 用途 | 备注 |
|---|---|---|---|
| 主角白模 | Mixamo `Y Bot` 或 Unity Starter Assets Armature | 主角占位模型 | 优先用于技术验证，不追求最终观感 |
| 敌人白模 | Mixamo `X Bot` 或低模人形角色 | 敌人占位模型 | 便于区分本地玩家、远端玩家和敌人 |
| 基础移动 | Unity Starter Assets Third Person Controller | 移动、跳跃、镜头跟随 | 适合接入 Input System 和 Cinemachine |
| 基础动作 | Mixamo 动作库 | Idle、Run、Attack、Dodge、Hit、Death | 需要统一 Humanoid Rig 和 Animator |

验收标准：

- 能进入训练场景并控制角色移动。
- 角色至少具备 `Idle / Move / Attack / Dodge / Hit / Dead` 状态。
- 普攻、闪避、受击和死亡能触发对应动画。
- 2 个客户端能看到彼此的移动和基础动作变化。

---

### 3.2 阶段二：免费 / 低价合法补强

目标：在系统跑通后增强可读性和演示观感。

推荐素材：

| 类型 | 推荐来源 | 用途 | 选择标准 |
|---|---|---|---|
| 动作包 | Unity Asset Store、Kevin Iglesias、Mixamo | 普攻、翻滚、受击、死亡、施法 | 动作命名清晰、Humanoid 兼容、License 明确 |
| 技能特效 | Unity Asset Store 免费 VFX、Cartoon FX、War FX、自制 Particle / Trail | 刀光、命中特效、投射物 | 不追求华丽，优先清楚表达技能事件 |
| 武器 | Unity Asset Store、Kenney、Quaternius、Sketchfab 合法资源 | 剑、法杖、弓、投射物 | 风格统一、低成本、可商用或可用于作品集 |
| 场景 | Kenney、Quaternius、Unity Asset Store 免费环境包 | 训练场、出生点、边界、障碍物 | 小场景优先，便于性能和网络验证 |
| UI 图标 | Unity Asset Store、Kenney、自制简单图标 | 技能图标、状态图标 | 能表达功能即可，不依赖商业 IP |

验收标准：

- 战斗画面能清楚看出攻击范围、命中反馈、血量变化和角色状态。
- 技能 VFX 不遮挡 Debug 信息，不影响网络同步观察。
- 场景规模可控，适合本机 2 客户端演示。
- 所有引入素材都登记到本文档的许可表。

---

### 3.3 阶段三：作品集展示替换

目标：在 MVP 完成后，替换为更统一、更适合录屏的合法素材。

可选方向：

- 购买一套风格统一的动作 RPG 角色、武器、场景和 VFX 包。
- 使用原创或外包角色，但保持骨骼结构兼容 Humanoid。
- 保留白模版本作为技术调试模式，在正式演示中切换到展示素材。

替换原则：

- 不因为好看而破坏已有动作状态机、同步协议和资源加载结构。
- 新素材必须先在测试场景中验证动画重定向、碰撞盒、特效生命周期和 GC Alloc。
- 如果素材 License 要求署名，必须在 README 或专门 Credits 中保留署名。

## 4. 技能与动作模组设计

技能系统第一版以“技术骨架”优先，而不是美术复杂度优先。

推荐 `SkillDef` 字段：

```text
SkillDef
  skillId
  displayName
  animationKey
  vfxKey
  castTime
  hitFrameStart
  hitFrameEnd
  range
  angle
  radius
  damage
  cooldown
  moveLock
  canCancelWindow
  networkEventType
```

MVP 技能类型：

| 技能类型 | 展示价值 | 美术实现方式 |
|---|---|---|
| 普攻三连 | Animator、Combo Window、HitBox 时序 | Mixamo / 动作包攻击动作 + 简单 Trail |
| 闪避 | 输入响应、位移控制、无敌帧窗口 | Roll / Dash 动作 + 透明度或残影提示 |
| 单体技能 | 前摇、命中判定、伤害事件、网络广播 | Slash VFX 或 Projectile |
| 受击 / 死亡 | Server Authoritative 血量、表现同步 | Hit Reaction / Death 动作 |

面试时重点讲技术结构：

- 技能由配置驱动，动画和 VFX 通过 key 引用资源。
- 命中窗口由帧事件或时间轴控制，避免整段动画都可命中。
- 客户端负责输入和表现，服务端负责血量、死亡和结算等权威结果。
- 远端角色播放同步事件，本地角色优先保证输入反馈。

## 5. Unity 导入规范

### 5.1 模型与动画

- 人形角色优先设置为 `Humanoid` Rig。
- 同一角色的动作统一使用相同 Avatar 或可兼容 Avatar。
- 动作文件命名保持语义清晰，例如：

```text
Anim_Player_Idle.fbx
Anim_Player_Run.fbx
Anim_Player_Attack01.fbx
Anim_Player_Dodge.fbx
Anim_Player_Hit.fbx
Anim_Player_Death.fbx
```

- 只保留 MVP 需要的动作，不一次性导入大量未使用动画。
- 导入后记录 Root Motion 是否启用，避免网络同步和本地移动控制冲突。

### 5.2 VFX 与材质

- 技能特效使用独立 Prefab，并通过 Addressables key 加载。
- 特效生命周期必须可控，避免场景中残留未释放对象。
- 早期优先使用简单 Particle、Trail 和命中闪光，不追求复杂 Shader。
- 每个 VFX 至少验证：播放、停止、复用、销毁或回池。

### 5.3 场景与资源加载

- 战斗场景优先小而清晰：训练场、出生点、边界、少量障碍物。
- 场景和角色资源后续统一接入 Addressables。
- Loading UI 显示真实加载进度，而不是纯假进度条。
- 资源释放和重复加载要记录在性能验证文档中。

## 7. 仓库与发布规则

- 不把第三方付费素材原始包直接提交到公开 GitHub。
- 对于可再下载的商店素材，只提交自己的脚本、配置、场景引用和必要说明。
- 如果素材 License 不允许再分发，公开仓库中不得包含原始模型、贴图、动画、音频或特效文件。
- 如果演示视频中使用了需要署名的素材，在 README 或视频说明中补 Credits。
- Build 包如果包含第三方素材，仅用于符合 License 的作品集演示，不把素材作为可独立提取资源分发。

## 8. 求职表达口径

可以这样描述本项目素材策略：

> 本项目美术上采用合法授权的白模和低成本素材，重点展示客户端工程链路。我把素材来源和许可作为项目交付的一部分管理，避免使用未授权商业 IP，同时保证动作状态机、技能事件、网络同步、Addressables 加载和性能验证都可以被清楚演示。

面试中不强调“素材像某某商业游戏”，而强调：

- 我如何用白模快速验证动作和同步逻辑；
- 我如何设计可替换的 `animationKey` / `vfxKey`；
- 我如何区分本地表现、远端表现和服务端权威结果；
- 我如何记录素材来源、License 和可复现演示证据。

## 9. 下一步

在迭代 0 / 迭代 1 之前，素材侧只需要完成以下准备：

1. 确认 Unity Starter Assets 是否导入客户端工程。
2. 确认 Mixamo 或替代白模动作来源是否可用。
3. 建立 `Assets/_Project/Art/Placeholder/` 或等价目录，用于存放占位模型、动画和 VFX。
4. 每导入一个素材，就补充一次许可登记表。
5. 等 WebSocket Ping / Pong 和登录链路跑通后，再正式推进角色动作与技能素材。
