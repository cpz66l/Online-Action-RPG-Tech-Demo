# Online Action RPG Tech Demo 迭代模块规划

> 文档版本：v0.1 规划版  
> 创建日期：2026-08-13  
> 关联文档：[项目立项书](项目立项书.md)、[系统架构设计](系统架构设计.md)、[协议设计](协议设计.md)  
> 规划方式：按模块迭代，不绑定固定周数；每个迭代必须有可演示验收物

---

## 1. 迭代原则

- 先闭环，再扩展。
- 每个迭代都必须能运行、能截图、能记录问题。
- 不以“技术名词覆盖率”为目标，以“商业客户端链路可解释”为目标。
- 同一阶段只解决少数关键问题，避免登录、网络、动作、热更、Boss 同时开坑。
- 每个迭代结束后都要补开发日志、Bug 记录和验证证据。

## 2. 迭代 0：项目骨架与通信验证

目标：客户端和服务端能连起来。

### 产出

- Unity 空工程；
- C#/.NET 服务端空工程；
- WebSocket 连接；
- `PingReq / PingRes`；
- 客户端网络日志面板；
- 服务端连接日志。

### 验收

- 启动服务端后，客户端能连接成功。
- 客户端能发送 Ping，服务端返回 Pong。
- 客户端能显示 RTT。
- 断开服务端后，客户端能显示断线提示。

### 证据

- 运行截图；
- 协议日志；
- 服务端控制台输出；
- 本阶段开发日志。

## 3. 迭代 1：账号登录闭环

目标：做出商业客户端入口。

### 产出

- Login UI；
- RegisterReq / RegisterRes；
- LoginReq / LoginRes；
- Token 保存；
- 登录错误提示；
- 登录成功进入大厅。

### 验收

- 新账号能注册。
- 已注册账号能登录。
- 重复注册有错误提示。
- 错误密码有错误提示。
- 登录成功后客户端保存 Token 并进入 Lobby。

### 证据

- 登录流程录屏；
- 成功 / 失败协议日志；
- 错误码截图。

## 4. 迭代 2：大厅房间闭环

目标：多人进入同一个房间，准备并开始战斗。

### 产出

- Lobby UI；
- 房间列表；
- CreateRoom；
- JoinRoom；
- LeaveRoom；
- Ready；
- StartBattle；
- RoomStateNtf。

### 验收

- 客户端 A 创建房间。
- 客户端 B 加入房间。
- 两个客户端都能看到成员和准备状态。
- 非房主不能开始战斗。
- 房主开始战斗后，两个客户端进入加载流程。

### 证据

- 双客户端截图；
- 房间状态广播日志；
- 错误分支记录。

## 5. 迭代 3：异步资源与场景流

目标：从大厅加载到战斗场景，展示真实资源加载链路。

### 产出

- Addressables 初始化；
- Loading UI；
- 战斗场景异步加载；
- 角色 Prefab 加载；
- 技能特效加载；
- ClientLoadProgressNtf；
- ClientBattleReadyReq；
- BattleStartNtf。

### 验收

- Loading UI 显示真实加载进度。
- 两个客户端都加载完成后才进入战斗开始。
- 加载失败能提示并允许重试或返回大厅。
- 战斗结束后能释放战斗资源。

### 证据

- 加载耗时记录；
- Addressables 日志；
- 加载失败模拟截图；
- 资源所有权说明。

## 6. 迭代 4：本地动作战斗原型

目标：先让单人动作战斗可玩，再接网络同步。

### 产出

- 第三人称移动；
- Cinemachine 镜头；
- 目标锁定；
- 普攻 3 连段；
- 闪避；
- 1 个主动技能；
- HitBox / HurtBox；
- 受击、硬直、击退；
- HP 和死亡。

### 验收

- 单机训练场能完成移动、锁定、普攻、闪避、技能、受击和死亡。
- HitBox / HurtBox 能可视化调试。
- 技能配置不写死在角色脚本里。

### 证据

- 单机动作演示录屏；
- 技能配置截图；
- HitBox 可视化截图；
- 动作状态机说明。

## 7. 迭代 5：基础网络同步

目标：两个客户端能看到彼此的移动和基础状态。

### 产出

- PlayerInputCmd；
- BattleSnapshotNtf；
- 服务端 Tick；
- 位置同步；
- 朝向同步；
- 远端玩家插值；
- 网络状态面板。

### 验收

- 客户端 A 移动时，客户端 B 能看到远端角色移动。
- 远端角色移动不明显抖动。
- Debug 面板能显示 tick、RTT、快照延迟和插值缓冲数量。

### 证据

- 双客户端同步录屏；
- 快照日志；
- 插值参数记录；
- 弱网前后对比。

## 8. 迭代 6：战斗事件同步

目标：攻击、技能、受击、血量和结算能联机同步。

### 产出

- PlayerActionCmd；
- BattleEventNtf；
- PlayerHpNtf；
- PlayerDieNtf；
- BattleResultNtf；
- 本地动作表现和服务端权威血量对齐。

### 验收

- 客户端 A 攻击，客户端 B 能看到动作和受击反馈。
- 血量以服务端广播为准。
- 死亡后不能继续发送有效战斗操作。
- 战斗结束后两个客户端看到一致结算。

### 证据

- 战斗同步录屏；
- 战斗事件日志；
- HP 变化日志；
- 非法操作错误码记录。

## 9. 迭代 7：调试与弱网工具

目标：让同步问题可观察、可复盘。

### 产出

- 协议日志面板；
- RTT 显示；
- 延迟模拟；
- 丢包模拟；
- GM 指令；
- 玩家状态面板；
- 房间 / 战斗状态面板。

### 验收

- 能手动模拟延迟和丢包。
- 能查看最近协议包。
- 能查看本地 / 远端玩家状态。
- 能用 GM 指令触发回血、死亡、重置战斗等测试流程。

### 证据

- Debug 面板截图；
- 弱网模拟前后录屏；
- GM 指令日志。

## 11. 迭代 9：加分扩展候选

本阶段只在 MVP 完成后选择 1-2 个高价值方向，不同时展开。

| 扩展 | 价值 | 风险 |
|---|---|---|
| SQLite 持久化 | 展示账号数据落盘 | 后端时间增加 |
| MessagePack / Protobuf | 展示协议工程化 | 需要协议生成或映射维护 |
| KCP / UDP | 更接近实时同步讨论 | 调试复杂度上升 |
| 客户端预测 | 同步面试加分 | 难度高，容易拖慢项目 |
| xLua 数据 / 技能热更 | 国内商业项目常见 | 不宜过早接入 |
| 简单 Boss | 提升演示观感 | 容易变成玩法项目 |
| 技能 Shader / 特效 | 靠近动作 RPG 表现 | 需要图形学和美术时间 |

## 12. 每个迭代的记录要求

每个迭代结束后必须补充：

- 开发日志；
- Bug 记录；
- 验收截图或录屏；
- 协议或架构变更；
- 性能或调试证据；
- 下一迭代风险。

这些材料后续应整理进 `C:\Users\cp\knowledge-base` 的学习区和正式知识页面。
